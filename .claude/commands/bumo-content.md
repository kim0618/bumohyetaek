# 부모혜택 콘텐츠 작성

> 2026-11-04 개정: 10/12 영구 동결이 풀리고 **사이트 주 3편 + 네이버블로그 주 3편**으로 재가동(주제는 서로 독립)(CLAUDE.md 최상단 규칙). 제이퍼 `/blog` 스킬의 요일 게이트·트리거·원문 검증·원장 등재 규칙을 이식했다. 목표 채널은 네이버(구글은 무반응).

## 0. 발행 요일 게이트 (다른 무엇보다 먼저 확인)

**발행 요일: 월요일 · 화요일 · 목요일 (주 3편)**

> 2026-11-09 변경: 일·화·목 → **월·화·목**(사용자 결정, 제이퍼 사이트 블로그 `/blog`와 같은 요일로 맞춤).

네이버블로그(월·수·금)와 주제·일정은 독립이다. 블로그는 미리 예약 발행하므로 사이트 글과 짝을 맞추지 않는다.

작업 시작 즉시 실제 요일을 확인한다. **날짜를 보고 요일을 추측하지 말 것.**

```bash
date +"%Y-%m-%d (%a) u=%u"   # u: 1=월 2=화 3=수 4=목 5=금 6=토 7=일
```

- `u`가 **1·2·4**(월·화·목)이면 → 그대로 진행한다.
- 그 외 요일이면 → **글을 쓰지 말고 멈춰서 알린다.** 주제 선정도 하지 않는다.

**비발행일 알림 문구 (그대로 사용):**
> 오늘은 YYYY-MM-DD **N요일**로 부모혜택 발행 지정 요일(월·화·목)이 아닙니다. 그래도 작성할까요? "진행"이라고 하시면 쓰겠습니다.

사용자가 "진행", "그래도 써", "오늘 써" 등으로 명시 지시하거나, 요일을 알고 지시한 경우("수요일인데 하나 써줘")는 작성한다. 알림 없이 임의로 진행하지는 않는다.

### 시작 전 기록 공백 확인
이 파일의 큐·발행 기록은 다른 PC·세션에서 갱신이 빠질 수 있다. 시작할 때 아래 두 줄로 이 파일 마지막 수정 이후 새 글이 있었는지 본다. 있으면 큐의 `[완료]` 표기부터 맞춘다.
```bash
git log --oneline -3 -- .claude/commands/bumo-content.md
git log --diff-filter=A --format='%ad %s' --date=short -5 -- 'src/data/articles/*/*.ts'
```

## 편수 원칙
- **사용자가 명시하지 않으면 1편만 작성한다.** (지정 요일 1일 = 1편)
- 사용자가 "2편", "3개" 등 명시한 경우에만 그 수를 따른다.
- 한 주에 3편을 넘기지 않는다. 사용자가 추가를 지시하면 따르되, 주 3편을 넘긴다는 사실을 먼저 알린다.

**왜 주 3편인가:** 시니어 돈·건강 정보(YMYL)는 편당 사실 주장이 수십 개라 편수를 늘리면 오류가 같이 는다. 제이퍼 `/blog`가 주 7편 → 주 3편으로 줄인 근거(검증 회차 약 80건 중 "오류 0건" 1건)와 같다. 편당 검증 깊이(법령·고시 원문까지)를 확보하는 쪽을 택한다.

조건에 맞으면 "다음 1편 우선 지정"에 넣고 이번 회차에 쓴다. 시행일이 3개월보다 멀면 Tier 2에 시행일과 함께 적어 두고 그때 쓴다.
기존 글에 해당 제도가 있으면 새 글 대신 기존 글 수치를 고칠지 먼저 판단한다(급증 페이지는 본문 수치만). 바뀐 금액·대상이 큰 뉴스면 새 글 + 기존 글 수치 정정을 둘 다 한다.
블로그도 같은 정책을 쓸 만하면 결과 요약 끝에 "블로그 주제 후보: (정책명, 확정 근거)"를 한 줄 남긴다. 블로그 일정은 사용자가 정한다.
신규 정책은 2차 자료가 거의 없어 웹 요약이 틀리기 쉽다. **보도자료·고시 원문**으로만 숫자를 쓴다.

## 구조 다양화 규칙 (핵심 - 반드시 적용)

### FAQ 개수 다양화
매번 3개 고정하지 않는다. 글마다 아래 분포로 작성:
- 2개: 간단한 주제 (~20%)
- 3개: 일반 주제 (~40%)
- 4개: 심화 주제 (~30%)
- 5개: 복잡한 주제 (~10%)

같은 주에 작성하는 글끼리도 FAQ 개수를 다르게 한다.

### 도입부(첫 번째 text 섹션) 톤 다양화
**7가지 패턴을 돌려 사용. 직전 3개 글과 다른 패턴 사용 필수:**
1. 질문형: "부모님이 ~하신다면 어떻게 해야 할까요?"
2. 결론 먼저: "결론부터 말하면, ~입니다."
3. 상황 묘사: "갑자기 ~한 상황이 생겼을 때..."
4. 통계/팩트: "만 65세 이상 노인 중 ~%가..."
5. 반전: "~라고 생각하기 쉽지만, 실제로는..."
6. 공감형: "~때문에 걱정이 많으시죠."
7. 비교형: "A와 B 중 어떤 것이 더 유리할까요?"

### 섹션 타입 다양화
text + list만 쓰지 않는다. 글마다 아래 중 2개 이상 포함:
- info 박스 (금액/기준 강조)
- tip 박스 (실천 가능한 팁)
- warning 박스 (주의사항)
- numbered-list (순서가 있는 절차)

### h2(heading) 제목 스타일 다양화
매번 "~란?", "~방법"만 쓰지 않는다:
- "~의 진실", "왜 ~인가", "~할 때 주의할 점", "~비교", "~체크리스트"

### 문체 다양화
- "~정리합니다", "~알아보겠습니다" 전체 글에서 1회 이하
- 중간중간 짧은 문장(10자 이하) 섞기: "핵심은 이겁니다."
- 일부 섹션에서 필자 판단 넣기: "개인적으로는 ~가 더 낫다고 봅니다"
- 독자에게 말 거는 톤 섞기: "여기서 주의할 점이 하나 있는데요."

### 4. 정책 수치 마스터 리스트 등재 = 발행 조건

`/home/tjd618/bumohyetaek/policy-data-points.md`가 검증된 수치의 단일 원장이다. `/bumo-refresh`가 이 원장을 기준으로 점검하므로, **등재하지 않은 수치는 영구히 갱신 사각지대에 남는다.** 새 글이 정책 수치를 담으면 등재 없이 발행을 마치지 않는다(사용자에게 묻지 않고 등재한다).

1. 새 글의 `sections`, `summary`, `keyPoints`, `seoDescription`, `faq`에서 금액(`[0-9,]+원`, `[0-9]+만\s*원`)·비율(`[0-9.]+%`)·연령·기간·정책 키워드를 뽑는다.
2. **기존 항목과 일치**: 해당 항목의 "영향 글" 목록에 새 slug 추가
